# RFC 011: the flow with its APIs (draft for the "Flow & APIs" section)

Working draft, not RFC text. Each step says who acts, what happens and why, in a few lines, then shows the APIs it introduces, trimmed to the fields that carry a design decision. Field names follow `platform-mesh/apis/providers/v1alpha1`, `provider-sdk/api/v1alpha1` and `provider-protocol/connections/v1` as of 2026-10-22.

Running example: Provider "Wild West", Base URL `https://wildwest.example.com/pm`; Owner `alice` in `:root:orgs:acme:alice`; `Provider` `wildwest`; Provider Workspace `2x8k9abc` hosted on shard `root`; a consumer later on shard `nereus`.

| Step | Who | APIs introduced |
|---|---|---|
| 0. Before anything happens | PM Administrators, Provider Administrators, `provider-gateway` | `ServerKey` |
| 1. Get a token | Owner, Provider's portal | `OnboardingToken` |
| 2. Create the `Provider` and the request | Owner | token `Secret`, `Provider`, `ProviderOnboardingRequest` |
| 3. Prepare the Provider Workspace | `platform-mesh-operator` | Connection Export and its binding |
| 4. Register | `platform-mesh-operator`, `provider-gateway` | `ProviderEndpointRegistration` and its `Secret`, Registration, `Connection`, kubeconfig `Secret` |
| 5. First Control Call | `platform-mesh-operator`, `provider-gateway` | Control Session, `GET` |
| 6. Write the `ProviderEndpoint` | `platform-mesh-operator` | `ProviderEndpoint` |
| 7. Open Sessions | Connectors, `provider-gateway` | Session, Hello |
| 8. Confirm kcp is reachable | `platform-mesh-operator` | — (the same `GET`) |
| 9. Run | the Provider's operator, `provider-gateway`, Connectors | `CONNECT` |
| 10. Change credentials | cert-manager, `platform-mesh-operator`, Connectors | `PUT …/connector-ca-set`, `ConnectorCASet` |
| 11. Offboard | Owner, `platform-mesh-operator`, `provider-gateway` | `DELETE` |

---

## 0. Before anything happens

**PM Administrators** deploy one Connector per kcp shard, and a Connector CA managed by cert-manager, which issues each shard's Connector a short-lived Connector Certificate. **Provider Administrators** install `provider-gateway` and route the Base URL's `/v1/connections/…` paths to it through their Edge, which only has to pass WebSockets. On its first start, **`provider-gateway`** generates a Server Key: the keypair through which the PM-side will recognise this Provider from now on.

```yaml
apiVersion: provider-sdk.platform-mesh.io/v1alpha1
kind: ServerKey                       # Provider's cluster; generated by provider-gateway
metadata:
  name: sk-2026-10
  namespace: wild-west-system
spec:
  retireAt: null                      # set by Provider Administrators to rotate the key
status:
  publicKey: "-----BEGIN PUBLIC KEY-----…"
  fingerprint: key-sha256:3f9a…       # what tokens name, and what the PM-side pins
# the private key is in the Secret sk-2026-10, readable only by provider-gateway
```

## 1. The Owner gets an Onboarding Token

**The Owner** asks the **Provider's portal** to connect their PM workspace. The portal issues a single-use, short-lived Onboarding Token, bound to the Owner's account and to one Server Key, and shows it once. The token names the Base URL, so it's only ever sent to its issuer, and the Server Key's fingerprint, so the PM-side can check during Registration that it talks to the real Provider-side. The Provider-side keeps only a hash of its secret.

```yaml
apiVersion: provider-sdk.platform-mesh.io/v1alpha1
kind: OnboardingToken                 # Provider's cluster; created by the portal
metadata:
  name: t-q8m2vxk3j7p4w9n2c5h8r6t1aa  # the token ID
  namespace: wild-west-system
spec:                                 # immutable
  owner: alice@example.com
  expiresAt: "2026-10-22T09:30:00Z"
  tokenHash: sha256:…                 # the token secret itself is never stored
  serverKey: sk-2026-10
status:
  registration:                       # set once spent: single use
    connectionID: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
    at: "2026-10-22T09:12:00Z"
```

```
pm1.<base64url(https://wildwest.example.com/pm)>.<key-sha256 of sk-2026-10>.<tokenID>.<tokenSecret>
```

Whoever reads the token before PM uses it can register a Connection in the Owner's name, so the path from the portal to PM is trusted. It gives no access to any existing Connection.

---

## 2. The Owner creates the `Provider` and the request

**The Owner** creates, in any order, the token as a `Secret`, a remote `Provider`, and a `ProviderOnboardingRequest` naming both. The `Provider` is the long-lived object, on which everything after Registration is reported; the request is a one-off action that spends the token. Its spec is immutable and names the token's ID, so the token can't be swapped under a running request.

```yaml
apiVersion: v1
kind: Secret                          # Owner's workspace
metadata:
  name: wildwest-token
  namespace: default
stringData:
  token: pm1.…                        # deleted by platform-mesh-operator once spent
---
apiVersion: providers.platform-mesh.io/v1alpha1
kind: Provider                        # Owner's workspace
metadata:
  name: wildwest
spec:
  remote:                             # marks a Remote Provider
    caBundle: ""                      # optional: private CA(s) for the Base URL's outer TLS
status:                               # written only by platform-mesh-operator
  phase: Ready                        # Pending → Provisioning → Ready ⇄ Degraded, Deleting
  conditions:                         # one per step: Workspace, ConnectionBinding,
    - type: Ready                     #   ConnectorAccess, Registered, Connected; and Ready
      status: "True"
  connection:                         # for the Owner's information only, never used by PM
    url: https://wildwest.example.com/pm
    connectionID: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
---
apiVersion: providers.platform-mesh.io/v1alpha1
kind: ProviderOnboardingRequest       # Owner's workspace
metadata:
  name: wildwest-2026-10-22
spec:                                 # immutable
  providerRef: { name: wildwest }
  tokenSecretRef: { namespace: default, name: wildwest-token, key: token }
  tokenID: t-q8m2vxk3j7p4w9n2c5h8r6t1aa
status:
  phase: Registered                   # Pending → Registering → Registered, or Failed
  connectionID: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
```

## 3. `platform-mesh-operator` prepares the Provider Workspace

As soon as the `Provider` exists, **`platform-mesh-operator`** creates its Provider Workspace and the ServiceAccount the Provider will act as in kcp, and binds PM's Connection Export into it. Before any access is granted, it puts admission policies in place that keep the Provider, though admin in its workspace, from granting rights or credentials to anyone outside it, and confirms they're enforced. Then it lets the Connectors mint tokens for that ServiceAccount. No kubeconfig is created: the Provider never holds a kcp credential.

The Connection Export serves one kind, `ProviderEndpoint` (step 6), and lets Connectors read the workspace's endpoint slices, to see which shards the Provider has consumers on (step 7). Its maximal permission policy keeps `ProviderEndpoint`s written only by PM, whatever the Provider's rights in its workspace.

```yaml
apiVersion: apis.kcp.io/v1alpha2
kind: APIExport                       # :root:providers:system
metadata:
  name: connections.providers.platform-mesh.io
spec:
  resources:
    - group: providers.platform-mesh.io
      name: providerendpoints         # the only kind it serves
  permissionClaims:
    - group: apis.kcp.io
      resource: apiexportendpointslices
      verbs: [get, list, watch]       # read-only
  maximalPermissionPolicy:
    local: {}                         # everyone may read ProviderEndpoints,
                                      # only platform-mesh-operator may write them
---
apiVersion: apis.kcp.io/v1alpha2
kind: APIBinding                      # Provider Workspace; created by platform-mesh-operator
metadata:
  name: connections.providers.platform-mesh.io
spec:
  reference:
    export: { path: root:providers:system, name: connections.providers.platform-mesh.io }
  permissionClaims:
    - group: apis.kcp.io
      resource: apiexportendpointslices
      verbs: [get, list, watch]
      selector: { matchAll: true }
      state: Accepted
```

## 4. Registration

**`platform-mesh-operator`** first generates the Connection Secret and stores it, so a crash can never lose it. Then it opens a WebSocket to the token's Base URL and, inside it, runs the Inner TLS, accepting only the Server Key the token names. From here on the Provider's Edge sees only encrypted bytes. Inside, it presents the token's secret, the hash of the Connection Secret, and the Connector CA the Provider-side should trust for Sessions.

**`provider-gateway`** checks and spends the token, creates the Connection, and returns its ID and its Server Keys, which PM pins. No usable secret crosses the wire: only a spent token, a hash and public keys. A lost response is safe to retry: the same request gets the same answer.

```yaml
apiVersion: providers.platform-mesh.io/v1alpha1
kind: ProviderEndpointRegistration    # PM's runtime cluster; authoritative record of one Connection
metadata:
  name: 2x8k9abc                      # the Provider Workspace's logical cluster
  namespace: platform-mesh-system
spec:
  connectionID: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
  url: https://wildwest.example.com/pm
  serverKeys: ["-----BEGIN PUBLIC KEY-----…"]   # pinned
  unusedExpiresAt: "2026-10-29T09:30:00Z"       # removed by the Provider-side if never reached
---
apiVersion: v1
kind: Secret                          # PM's runtime cluster, never in kcp
metadata:
  name: 2x8k9abc-secret
  namespace: platform-mesh-system
stringData:
  secret: pmc1_…                      # the Connection Secret; the Provider-side stores only its hash
  pendingSecret: ""                   # only while it changes
```

```http
GET /pm/v1/connections/register/t-q8m2vxk3j7p4w9n2c5h8r6t1aa HTTP/1.1
Host: wildwest.example.com
Upgrade: websocket
                                      # no credentials; an unusable token is refused here
```

Inner TLS (ALPN `pm-register/1`), accepting only the Server Key whose fingerprint is the token's `keyfp`; inside it:

```http
POST /v1/connections HTTP/1.1
Authorization: Bearer <tokenSecret>

{
  "idempotencyKey": "<the request's UID>",
  "clusterName":    "2x8k9abc",
  "secretHash":     "sha256:<hash of the Connection Secret>",
  "connectorCASet": "-----BEGIN CERTIFICATE-----…"
}
```

```http
HTTP/1.1 201 Created

{
  "connectionID":    "c-7f3k9q2mx8w4h6j1n5p3r7t9vb",
  "serverKeys":      [ { "publicKey": "-----BEGIN PUBLIC KEY-----…" } ],
  "unusedExpiresAt": "2026-10-29T09:30:00Z"
}
```

On the Provider-side, the Connection and a kubeconfig for the Provider's operator:

```yaml
apiVersion: provider-sdk.platform-mesh.io/v1alpha1
kind: Connection                      # Provider's cluster; written by provider-gateway
metadata:
  name: c-7f3k9q2mx8w4h6j1n5p3r7t9vb # the connectionID; consumer data is keyed by it
  namespace: wild-west-system
spec:
  registration:                       # immutable
    owner: alice@example.com
    clusterName: 2x8k9abc
    unusedExpiresAt: "2026-10-29T09:30:00Z"
  pinnedBundle: |                     # the Connector CA(s) Sessions are verified against
    -----BEGIN CERTIFICATE-----
    …
status:
  conditions:
    - type: Ready                     # the workspace and every host the operator uses
      status: "True"                  #   are reachable over Sessions
  lastSeen: "2026-10-22T09:13:00Z"
  secretHash: sha256:…                # only the hash of the Connection Secret
---
apiVersion: v1
kind: Secret                          # Provider's cluster; read by the Provider's operator
metadata:
  name: connection-c-7f3k9q2mx8w4h6j1n5p3r7t9vb
  namespace: wild-west-system
  labels:
    provider-sdk.platform-mesh.io/connection: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
stringData:
  kubeconfig: |
    apiVersion: v1
    kind: Config
    clusters:
    - name: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
      cluster:
        server: https://front-proxy.pm.invalid/clusters/2x8k9abc   # placeholder, never resolved
        proxy-url: https://c-7f3k9q2mx8w4h6j1n5p3r7t9vb:<credential>@provider-gateway.wild-west-system.svc:3128
        tls-server-name: provider-gateway.wild-west-system.svc     # TLS to the gateway, not to kcp
        certificate-authority-data: <provider-gateway's CA>
    users:
    - name: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
      user: {}                        # no kcp credential
    contexts:
    - name: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
      context: { cluster: c-7f3k9q2mx8w4h6j1n5p3r7t9vb, user: c-7f3k9q2mx8w4h6j1n5p3r7t9vb }
    current-context: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
```

`platform-mesh-operator` then stores the result, deletes the spent token from the Owner's `Secret`, and marks the request `Registered`.

## 5. The first Control Call

Before telling any Connector about the Connection, **`platform-mesh-operator`** makes sure it can reach the Provider-side for upkeep. It opens a Control Session, again with Inner TLS against a pinned Server Key, and authenticates with the Connection Secret, which therefore never crosses the Edge readable. **`provider-gateway`** answers with the Connection's status, its Server Keys and what it pins; if the pinned Connector CA is out of date, PM pushes the current one (step 10). A Connection never gets Sessions unless its control path has worked at least once. If the Edge blocks it, the `Provider` says how.

```http
GET /pm/v1/connections/c-7f3k9q2mx8w4h6j1n5p3r7t9vb/control HTTP/1.1
Host: wildwest.example.com
Upgrade: websocket
PM-Server-Key: key-sha256:3f9a…       # which pinned key the Provider-side should present
```

Inner TLS (ALPN `pm-control/1`); inside it, any number of Control Calls:

```http
GET /v1/connections/c-7f3k9q2mx8w4h6j1n5p3r7t9vb HTTP/1.1
Authorization: Bearer pmc1_…          # the first failed check closes the Control Session
```

```http
HTTP/1.1 200 OK

{
  "workspace":         { "sessions": 0, "kcpReachable": false },
  "serverKeys":        [ { "publicKey": "-----BEGIN PUBLIC KEY-----…" } ],
  "pinnedBundle":      { "etag": "9a07…", "fingerprints": [ "cert-sha256:9a07…" ] }
}
```

## 6. `platform-mesh-operator` writes the `ProviderEndpoint`

**`platform-mesh-operator`** writes the Connection's `ProviderEndpoint` into the Provider Workspace, through the Connection Export: where Connectors should dial and which keys to pin. It's the only kcp object describing the Connection, and it lives next to the shard that hosts the workspace, so Connectors need nothing from PM's runtime cluster to find their Connections. Only PM can write it, and it's the only way a Connection Secret can ever change (step 10).

```yaml
apiVersion: providers.platform-mesh.io/v1alpha1
kind: ProviderEndpoint                # Provider Workspace; written only by platform-mesh-operator
metadata:
  name: default                       # one per Provider Workspace
spec:
  connectionID: c-7f3k9q2mx8w4h6j1n5p3r7t9vb
  url: https://wildwest.example.com/pm
  serverKeys: ["-----BEGIN PUBLIC KEY-----…"]
  caBundle: ""                        # copied from the Provider's spec.remote.caBundle
  pendingSecretHash: ""               # only while the Connection Secret changes
```

---

## 7. Connectors open Sessions

Every **Connector** watches all `ProviderEndpoint`s. The Connector of the shard hosting the Provider Workspace opens the first Session at once, so the Provider can reach its own workspace before it has any consumers. Connectors on other shards open theirs only when the Provider gets consumers there, which they see in its endpoint slices: Sessions follow traffic, and nothing is registered per shard.

Each Session is a WebSocket with mutual Inner TLS: the Connector presents its Connector Certificate, which **`provider-gateway`** accepts only if it was issued by a CA this Connection pins; the gateway presents a Server Key the Connector has pinned. One Connector Certificate serves every Connection of the PM Instance, so the Connector's first message, the Hello, names the Connection, and the gateway closes the Session if it doesn't match. Inside, a multiplexer lets the Provider-side open many independent Streams, one per HTTP connection.

```http
GET /pm/v1/connections/c-7f3k9q2mx8w4h6j1n5p3r7t9vb/session HTTP/1.1
Host: wildwest.example.com
Upgrade: websocket
                                      # no credentials
```

Inner TLS (ALPN `pm-session/1`), mutual; then the Hello:

```json
{
  "connectionID": "c-7f3k9q2mx8w4h6j1n5p3r7t9vb",
  "clusterName":  "2x8k9abc",
  "hosts":        [ "nereus.kcp.example" ],
  "sub":          "<opaque, for audit>"
}
```

`hosts` only tells the gateway which Session to use for which kcp host; it's routing, not proof. Then yamux; Streams carry plain HTTP/1.1.

## 8. `platform-mesh-operator` confirms kcp is reachable

**`platform-mesh-operator`** keeps polling the status `GET` from step 5. Once **`provider-gateway`** reports that its workspace and every host its operator uses are covered by a Session and reach kcp, the `Provider` becomes `Ready`. Owners see only that aggregate, never PM's shards.

```json
{
  "workspace":         { "sessions": 2, "kcpReachable": true },
  "virtualWorkspaces": { "nereus.kcp.example:443": { "sessions": 2, "kcpReachable": true } },
  …
}
```

## 9. Running

**The Provider's operator** uses its kubeconfig like any other: client-go sends `CONNECT` to **`provider-gateway`**, which picks one of the Connection's Sessions for that host and opens a Stream. The request travels without credentials. The **Connector** checks its path against what the Connection may reach (its own workspace, and its own exports' virtual workspace), refuses the few operations that would affect PM, adds a short-lived token for the Provider's ServiceAccount, and forwards it to kcp. The response streams back unchanged.

```http
CONNECT nereus.kcp.example:443 HTTP/1.1
Proxy-Authorization: Basic <c-7f3k9q2mx8w4h6j1n5p3r7t9vb:credential>

HTTP/1.1 200 Connection established
```

TLS to `provider-gateway`'s own certificate (`tls-server-name`); inside it, on a Stream:

```http
GET /services/apiexport/2x8k9abc/cowboys/clusters/<consumer>/apis/wildwest.dev/v1alpha1/namespaces/default/cowboys/billy HTTP/1.1
Host: nereus.kcp.example
                                      # no Authorization: the Connector adds the SA token
```

## 10. Changing credentials

Everything here is automatic, and none of it needs the Provider's operator to do anything.

- **Connector Certificates** last 24 hours; **cert-manager** renews them twice a day. Providers pin the Connector CA, not certificates, so they don't notice.
- **The Connector CA** is renewed by **cert-manager** once a year, with a new key. **`platform-mesh-operator`** pushes it to every Connection as a Control Call, never over a Session, so a stolen Connector Certificate can't plant a CA. **Connectors** switch to it only once every reachable Connection trusts it; the old CA is dropped later. The `ConnectorCASet` reports this, and is where PM Administrators distrust a leaked CA.
- **The Connection Secret** changes only through the `ProviderEndpoint` (`pendingSecretHash`), which only PM can write and which the Provider-side reads only over a verified Session. No call, token or portal account can change it.

```http
PUT /v1/connections/c-7f3k9q2mx8w4h6j1n5p3r7t9vb/connector-ca-set HTTP/1.1
Authorization: Bearer pmc1_…
If-Match: "9a07…"                     # replaced only if unchanged since PM read it

{ "connectorCASet": "-----BEGIN CERTIFICATE-----…(new CA)…-----BEGIN CERTIFICATE-----…(previous CA)…" }
```

```http
HTTP/1.1 204 No Content               # 412 Precondition Failed if it changed meanwhile
```

```yaml
apiVersion: providers.platform-mesh.io/v1alpha1
kind: ConnectorCASet                  # PM's runtime cluster
metadata:
  name: default                       # singleton
spec:
  distrust: []                        # written by PM Administrators: key-sha256 of leaked CAs
status:                               # derived; written by platform-mesh-operator
  certificates:                       # every unexpired issuance of the Connector CA
    - certFingerprint: cert-sha256:9a07…
      keyFingerprint: key-sha256:77d2…
      issued: "2026-10-13T08:00:00Z"
      notAfter: "2027-10-13T08:00:00Z"
      state: Current                  # Current | Previous | DistrustPending | Distrusted | Dropped
  conditions:
    - type: Converged                 # every reachable Connection trusts the current CA;
      status: "True"                  #   Connectors switch to it only then
```

## 11. Offboarding

**The Owner** deletes the `Provider`. **`platform-mesh-operator`** deletes the `ProviderEndpoint` first: every Connector closes its Sessions, and the Provider-side's access to kcp ends at once, whatever happens next. Then it tells **`provider-gateway`** to delete the Connection, as clean-up; an unreachable Provider doesn't block it. Finally it removes the `ProviderEndpointRegistration`, the Connector's access, the policies, the binding and the workspace. No kcp token was ever handed out, so there's nothing left to revoke.

```http
DELETE /v1/connections/c-7f3k9q2mx8w4h6j1n5p3r7t9vb HTTP/1.1
Authorization: Bearer pmc1_…
```

```http
HTTP/1.1 204 No Content
```

**`provider-gateway`** deletes the `Connection` and its kubeconfig `Secret`; the Provider's operator stops reconciling that Connection. Consumer data the Provider keeps elsewhere isn't deleted because a Connection went away.
